# 第 6 步 · 设置触摸屏软件

所有操作都在主机上做:7 英寸触摸屏加盖板上的硬件按键。本机按设计没有遥控。

## 盒内是怎么连的

```
安全主控 ESP32 ──Wi-Fi(盒内热点)──> 树莓派:盒内服务程序 server.py ──> 触摸屏(Chromium 全屏)
   │ 加热、泵、报警、指示灯、蜂鸣器、中止键                │ 本机界面 /local、自动记录 CSV
```

- 主控盒里的树莓派运行 `server.py`,并开一个只给 ESP32 用的 Wi-Fi 热点,自己的地址固定为 `10.42.0.1`。
- ESP32 连这个热点,每 2 秒把遥测发到 **`http://10.42.0.1:8080/api/device/telemetry`**,响应里带回触摸屏上排队的命令。
- 触摸屏全屏显示 `http://127.0.0.1:8080/local?dev=设备编号`,这是唯一的操作界面,按 [../1-design/touchscreen-ui.md](../1-design/touchscreen-ui.md) 做成监护仪式:顶栏是五步流程和计时;中间五个数字块(腹腔、药液、气体、腹压、雾化),颜色只表示状态;底栏是中止、这一步唯一的主按钮(或“升温中”“剩余 mm:ss”这样的状态)、详情。主屏没有句子。说明、报警处理步骤、全部读数和加热输出、曲线、设置、“不等腹腔直接就绪”“提前结束暴露”都在“详情”里。中止和提前结束要在全屏确认页上再确认。
- 加热、联锁、报警、指示灯、蜂鸣器、红色中止键都由安全主控自己管,不依赖树莓派。树莓派或热点出了问题,触摸屏不能操作,但主控照常保护和报警。
- ESP32 5 秒没有数据过来,触摸屏整屏显示“主控无响应”。
- 报警时顶栏整条变色(高级红色 2 Hz 闪,中级黄色),写“报警名 · 第一步动作”;喷雾阶段循环泵一停(雾化气没了,而注射泵不归本机管、还在推药),第一步动作永远是“停注射泵”。底栏换成“确认报警”和“消音”。
- **手术记录是自动的。** 从“开始预热”起到回到待机,每条遥测写一行 CSV,存在树莓派存储卡的 `~/hp-data/cases/` 下,手术结束后拷出来。结束阶段屏上会显示“本次记录已保存”和文件名。操作日志 `audit.jsonl` 也在同一个目录。

> 样机软件,没有登录和加密。树莓派只能接盒内热点,不要把它的网口或 Wi-Fi 接到医院网络。CSV 里没有病人信息,文件名是设备编号加时间。

接口、阶段、报警的含义以 [../1-design/interface-spec.md](../1-design/interface-spec.md) 为准。

## 在电脑上演示(不需要硬件)

任意一台装了 Python 3.9 以上的电脑,不需要安装任何依赖,页面不引用任何外网资源。开两个窗口:

```
cd 6-software
python server.py
python simulator.py http://127.0.0.1:8080 1 20
```

然后用浏览器打开 `http://127.0.0.1:8080/panel`。这一页画的是主机盖板:中间的屏幕就是真正的触摸屏界面,可以直接点;下排是指示灯、中止键、消音键、蜂鸣器。也可以直接打开 `http://127.0.0.1:8080/local`,看全尺寸的触摸屏界面。

`simulator.py` 代替 ESP32。三个参数依次是服务程序地址、设备台数、加速倍数;上面这行会出现一台 `HP-001`,时间加速 20 倍。模拟器里的升温快慢是随手取的数,**不能用来估计真机的升温时间**。

要看报警是什么样,加 `--fault`,写法是 `名称@开始秒数[+持续秒数]`,秒数按设备时间算:

```
python simulator.py http://127.0.0.1:8080 1 20 --fault noz_block@300+60,press_high@900
```

可用的名称:`ip_high`、`overtemp_drug`、`overtemp_gas`、`sensor`、`sensor_open`、`press_high`、`press_low`、`water_low`、`noz_block`、`noz_low`。各自的含义见 `python simulator.py --help`。

环境变量:`PORT`(默认 8080)、`HOST`(监听地址,默认 0.0.0.0)、`HP_DATA_DIR`(记录和日志放哪,默认本目录)。

## 设置树莓派

把整个 `6-software` 文件夹拷到树莓派(带桌面的 Raspberry Pi OS,Bookworm 或更新,网络由 NetworkManager 管),在文件夹里运行一次:

```
sh kiosk/setup-kiosk.sh HP-001 HP-001-box 热点密码至少8位
```

它会:装一个开机自启的 systemd 服务 `hp-server` 运行 `server.py`,记录放在 `~/hp-data`;用 `nmcli` 把 `wlan0` 设成热点(名称和密码是第二、三个参数,树莓派地址 `10.42.0.1`);桌面登录后等服务程序能连上,再用 Chromium 全屏打开本机界面。

**这个脚本从来没有在树莓派上运行过。** 第一次用请接显示器和键盘,对照输出逐步检查。

ESP32 固件里要填的服务程序地址:`http://10.42.0.1:8080`。

## 自测

```
python test_flow.py
```

脚本自己在 8091 端口起服务程序和模拟器,数据放临时目录,用触摸屏会调的接口走完一次手术,再查:拒绝的命令、自动开始和结束记录、CSV 内容、中止、故障注入(腹腔过温、喷头堵塞、雾化气压不足、喷雾中停泵)、曲线接口、离线判定、服务程序重启后数据和未结束的记录还在。装了 node 时还会跑 `common.js` 里判断“要不要叫人停注射泵”和指示灯的函数。约 70 秒,最后一行应为 `ALL PASS`。

## 已知的限制

- 命令在服务程序里排队,等 ESP32 下一次上报(2 秒一次)时带回去,所以触摸屏上点了以后最多约 2 秒才生效;排队超过 30 秒没被取走就作废。主控无响应时服务程序拒绝一切命令,这时要停机只能按红色中止键。
- 曲线数据只放在内存里(最近 2 小时),服务程序重启后曲线从头开始;手术记录 CSV 和操作日志在存储卡上,不受影响,没结束的记录重启后接着写。
- 服务程序默认监听树莓派的所有网口,所以树莓派只能接盒内热点。如果将来非接别的网络不可,要先用 `HOST=10.42.0.1` 把监听限制在热点上(这时触摸屏也要改用这个地址打开),目前没有这样做,也没有试过。
